# 联网搜索决策

## 做什么

根据**联网模式**、用户本轮问题、会话上文、本地知识库/问数证据，判断是否需要上网搜索，并给出实际搜词与可读原因。  
**本 Skill 只做决策，不执行搜索**；真正搜网由系统直调 MiniMax 官方搜索 HTTP 接口完成（与模型中心同一 API Key，无需本机 uvx）。

## 输入（由系统提供）

- `mode`：`off` | `auto` | `force`
- `query`：本轮用户问题
- `history`：同一会话近期对话（可能为空）
- `local_evidence`：本地 kb/data 证据摘要
- `explicit_web`：是否已判定用户明确要求上网（如「上网查」「搜一下」）

## 硬规则（系统会强制执行，你仍须遵守）

1. `mode=off`：必须 `should_search=false`，原因写「已关闭联网」。
2. `mode=force`：必须 `should_search=true`。
3. `explicit_web=true`：必须 `should_search=true`。
4. `mode=auto`：综合意图与本地是否够用再决定；本地已足够且问题不依赖外部/时效信息时，应跳过。

## 输出（只输出一个 JSON 对象，不要其它废话）

```json
{
  "should_search": true,
  "reason": "给用户看的短句，如：本地证据不足，需查公开政策更新",
  "search_query": "实际用于搜索的关键词，可与原问不同，更利于检索"
}
```

## 怎么判断（auto）

1. 先看会话上文：指代（「它」「那条线」「刚才说的」）要结合上文理解真实信息需求。
2. 本地证据已覆盖问题核心事实（站场参数、表数据、wiki 原文）→ 通常不搜。
3. 需要最新政策、新闻、官网公开信息，或本地明显不足 → 搜。
4. `search_query` 应简洁、含关键实体名；不要塞入无关指令。
