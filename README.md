# 战略规划域多源多模态知识大脑 · 项目手册

> **拷贝即用**的 Windows 桌面知识助手：Obsidian 管资料，**DeerFlow 二次开发**做智能；支持**轻量循证问答**与**多 Agent 报告**（油气管道工程建设等）。默认模型 **MiniMax M3**。  
> **主界面**：Vue 3 + Naive UI（左菜单业务系统布局）；DeerFlow React 前端已**封存**（菜单可打开，源码不删）。

**文档：** [PRODUCT](docs/PRODUCT.md) · [TECH](docs/TECH.md) · [ARCHITECTURE](docs/ARCHITECTURE.md) · [ROADMAP](docs/ROADMAP.md)

## 2. 基本准则（宪法摘要）

1. 便携桌面，无 Docker 主路径  
2. Obsidian Vault + DeerFlow 唯一智能主引擎（vendoring）  
3. **双路径**：普通问 = 检索±问数；「生成报告」= 全套子 Agent（可并行）  
4. Skill：**维护 / 查看 / 执行 / 导入**（P3 已交付；报告写作/评审可热替换 Skill）  
5. 国内 API，默认 MiniMax M3

## 3. 你怎么用（Vue 主界面）

界面文案**极简**（短标题 + 按钮动词 + 一句空态）。新手说明见系统**首次向导**与 Electron「帮助」。

**默认身份**：本产品对话与写作一律按「国家管网集团工作人员」理解「本集团 / 我司 / 我们」，不会再猜所属组织。

左侧菜单按 **研究 / 资产 / 系统** 分组：

| 菜单 | 做什么 |
|------|--------|
| **工作台** | 问答 / 问数 / 检索（与写作独立，不跳转写报告）。采用玻璃感三栏工作空间：左侧集中管理最近会话和紧凑知识范围卡片，中间按模式展示能力说明、常用问题与悬浮输入框，右侧统一承载证据溯源和执行轨迹；首页核心能力采用无按钮轮廓的静态摘要带，只有“试试这些问题”保留可点击卡片外观。**多会话永久保留**，同会话多轮有上下文；三栏宽度可左右拖拽（默认左 200 / 右 300，会记住）；问答等待时中栏会**逐步显示处理轨迹**；右侧证据栏同步最新一轮。用户可在输入区手动选择已启用的业务 Skill，或输入严格的 `/skill-id 问题` 临时覆盖，答案卡片和轨迹会标明实际 Skill 与触发原因；不选即走系统默认。答案引用 **[1][2]…**。**联网**：关闭 / 智能（默认）/ 强制——智能由 `web-search` Skill 判断，搜索直调 MiniMax 官方接口（便携包无需 uvx）；**看图**：关闭 / 智能（默认）/ 强制——用视觉角色（默认 MiniMax M3）读 Vault 图或工作台上传图，证据栏出 `viz:`；导入图片会预识图写入 `wiki/viz`；**问数**：站场/管段行级命中、实体名片；列条件筛选先弹确认卡，确认后合并总表 |
| **战略规划生成** | **独立功能**：从左侧导航进入时默认显示**新建任务页**，历史草稿、运行任务和已完成报告均由用户从任务列表主动打开或删除；新建页以大尺寸“写作目标”编辑区为主，目标读者与模板并列，知识范围使用紧凑类型标签，创建状态不展示空的知识卡片栏；页顶与工作台相同的**联网三档**（关闭/智能/强制，共用配置）。中间填写目标，并按与知识库一致的**文档、结构化数据、多媒体、知识卡片、实体关系、指标规则、报告成果**选择知识范围，可选一个客户业务 Skill 作为本任务的“写作方法”，再按需选择模板 → **智能补缺**（本地提取时间、区域、业务范围、目标、读者与硬约束；信息充分时自动跳过，时间/范围等标准缺口直接本地生成问题，仅复杂歧义才调用高速模型）→ 七步流水线（补缺→研究→架构→逐章写作→引用→评审→自动迭代）。客户 Skill 在创建时保存版本与正文快照，并用于大纲、逐章写作和评审；检索、问数、引用及安全约束仍由系统 Skill 管控。不选模板时由 AI 动态生成大纲，用户确认后再写正文。创建完成即进入统一写作工作台；页面百分比表示**正文完成度**，后台进度始终按完整七步展示，不会把一条补缺记录误显示成 `1/1=99%`。生成由后台任务继续执行，页面关闭或切走后不会终止；每章完成即保存检查点，重新打开会恢复已有正文并重新连接实时进度，Gateway 重启则在最近检查点暂停并可继续。过程中可调检索/问数，结果进右侧**知识卡片**；写作联网仅限 `config/web_whitelist.json` 白名单。产出可**在线编辑**，并下载 **Word / PDF / MD**（同时可落盘 Vault） |
| **知识库** | 面向用户的逻辑知识目录：按**文档、结构化数据、多媒体、知识卡片、实体关系、指标规则、报告成果**七种数据类型浏览；业务领域只作为标签，`raw` 只作为来源状态。支持知识首页、分类浏览、详情预览、智能导入与知识治理；物理 Vault 目录保持不变 |
| **知识图谱** | 自动 `[[双向链接]]` + 实体名片；ECharts 可点图谱；与 Obsidian 共用同一 Vault |
| **Skill** | 分两组：**业务场景**（可编辑/删除）与 **系统内置**（只读，不可改删），支持按名称/说明/标识搜索；新建采用「定义用途 → 配置规则 → 试跑发布」三步向导，草案试跑不落盘；详情底部默认**试跑**，可「开始优化对话」对业务 Skill 多轮改写（每 Skill 一份永久对话，可按条删/清空）；草案先写入编辑区，点「保存到 Skill」才落盘 |
| **模型** | 一套连接下登记多个模型；选主/高速/视觉/备用；支持 OpenAI 兼容与 Anthropic；调用记录 |
| **评测** | 示例黄金套件、异步跑批、逐题详情、分类评分、导入导出、报告/模型·Skill 对比（无假通过率） |
| **设置** | Vault、联网、看图、报告、健康检查、首次向导 |

Electron **顶栏菜单**：文件（Vault / 配置 / Obsidian）/ 视图（刷新、证据栏）/ 快捷（新建问答/报告、联网模式）/ 帮助（设置、关于、**高级**：开发者工具与 DeerFlow 旧界面）。功能页请用左侧菜单。

### 为什么用 Obsidian（对 RealAi 的增益）

| Obsidian 优势 | 对本项目的增益 |
|---------------|----------------|
| 纯本地 Markdown 文件夹（Vault） | 知识不锁死在数据库；便携拷贝、Git 备份都方便 |
| 双向链接 / 图谱 / 标签 | RealAi 导入/重建 Wiki 时自动写入 `[[链接]]` 与实体页；Obsidian 关系图谱与 RealAi「知识图谱」共用 |
| 强大编辑与插件生态 | 长文、模板、日报整理用成熟工具，RealAi 专注「问与写报告」 |
| 所见即文件 | 导入失败不写库、报告落盘 `vault/reports`，对人透明可查 |
| 可与 RealAi 并行打开 | **文件 → 打开 Obsidian** 进入本机 Obsidian 管理界面；RealAi 知识库页负责导入/检索侧 |

分工建议：**Obsidian = 人整理与浏览**；**RealAi = AI 问答、问数、写报告**。两边共用同一 Vault 路径（设置里配置）。

## 4. 报告写作流水线（仅「战略规划生成」页）

绑定战略规划 Skill，按序执行：

`intake`（智能补缺）→ `researcher` → `architect` → `writer`（逐章）→ `citer` → `reviewer` → `optimizer`（最多 5 轮）

- **智能补缺**：创建后先在本地提取时间、区域、业务范围、目标、读者和硬约束；信息充分时不检索、不调用模型，直接进入资料研究。缺少时间范围或业务范围等标准字段时，系统立即生成 1～2 个确定性问题，也不调用模型；仅目标本身存在复杂歧义时，才保留相关性最高的 3 条本地资料，并用快速模型在 12 秒、400 tokens 内生成结构化问题。Schema 校验失败时使用确定性兜底；答案写入「用户给定事实」。用户也可点「跳过补缺，直接生成大纲」，诊断中的耗时、模型错误和解析错误会持续保留。旧任务无补缺记录可直接运行。  
- 资料研究开始时先推送可见状态，再在工作线程中执行知识检索与结构化查询；本地知识、结构化数据和联网各有硬超时并可独立降级。检索优先：`vault/wiki` → `vault/raw` → 其他目录；只有目标包含数字、表格、指标、预测或计算意图时才启动结构化问数，避免普通报告无意义等待 NL2SQL；白名单联网结果进入知识卡片。  
- 写作**不能**编造证据包外的具体数字（用户给定事实可用于范围与叙事，数字仍须有 kb/data/web 证据）；报告类型的篇幅阈值仅用于后台质量控制，不在用户界面展示。  
- `writer` 使用模型原生 token 流；后端把可见正文以 SSE `chapter_delta` 连续推送，前端边接收边追加到当前章节。自动模式默认同时生成 3 章（可配置为 1–3），逐步确认模式保持单章串行；单次输出、分段续写和思考记录均设上限，避免长时间无可见反馈。  
- 大纲以**章节列表**展示（正式报告标题、章节、战略主线），架构步骤完成后即刷新；待确认时可改；需要时再看「原始数据」。**正文写作有不可绕过的大纲门禁**：空白、损坏或尚未确认的大纲只会回到确认页，不会提前进入逐章写作。系统会把用户写作指令提炼为正式报告标题，不把整段 query 当作标题，也不会把“自定义规划”“战略规划报告”“报告”等内部占位词当成标题；模型返回占位词时必须重拟，失败时从用户目标提炼兜底标题。模型若把思考过程写进正文，系统会自动去掉，只保留规范中文主线。  
- 步骤进度展示每步绑定的 **Skill ID**、实际调用的工具（检索/问数/联网等），以及 Skill 包内参考/脚本文件名（脚本默认不执行，仅列出）。旧任务会提示需新建重跑。  
- **步骤进行中或结束后可点击卡片**，查看本步过程记录（会随动作/模型调用完成自动刷新；非整字流式）：实际动作摘要、发给模型的提示词与回复（默认折叠可展开）、思考过程（接口未返回时显示「本步未提供」）。模型调用期间显示「模型生成中…」。改造前的旧任务点开会提示当时未记录。  
- 运行旁可 **暂停 / 继续 / 终止**：暂停与终止在「当前步骤或本章写完」后生效（不会卡在半句 LLM 中间）；暂停后点「继续」从断点接着跑；终止后状态为已终止，**已生成的预览正文与知识卡片保留**。  
- 预览区按**大纲章节一卡一章**展示（可展开、按章编辑保存）；大纲是章节编号与顺序的唯一来源，并发 token 不会自行创建或重排章节。断点恢复会从**首个缺失章节**继续，不能越过前面的空章；引用审核/优化后仍按大纲拆回卡片。思考过程（如 `<think>`）不会进入预览正文。另可「整篇编辑」。支持一键下载 **Word / PDF / Markdown**；保存编辑会同步重写 Vault 导出文件。  
- 引用审核和迭代优化采用**非破坏性提交**：候选稿先在后台校验章节完整性、正文保留比例和表格/审核输出污染，再进行复评分；只有正文完整且分数提升时才替换当前稿。引用审计表、评分卡、审核意见、缩水稿或未提分稿会被丢弃，页面始终保留上一版正文。  
- Skill 默认：`strategic-planning-intake` 与 `strategic-planning-*`（见设置中的七项 Skill ID）。细节见 [TECH.md](docs/TECH.md)。

## 6. 配置（系统管理 · US-09）

在 Vue **模型中心**统一管理模型（也可直接编辑 `config/settings.json`）；Vault / 联网 / 报告等在 **设置** 页：

| 项 | 说明 |
|----|------|
| 协议 | `openai_compatible`（默认，含 MiniMax）或 `anthropic` |

| Obsidian Vault 路径 | 轻量问答与报告的知识根目录 |
| 报告输出目录 / 逐步确认 / 七项战略 Skill 绑定 / 写作并发与生成上限 / 优化轮数 | 见 `report.*`（含 `writerConcurrency`、`writerMaxTokens` 等）；写作联网白名单见 `config/web_whitelist.json` |

| 默认看图模式 | 见 `search.visionMode`：`off` / `auto`（默认）/ `force`；关闭=零视觉 HTTP |
| 联网决策 Skill | 见 `search.webSearchSkillId`（默认 `web-search`）；只判断要不要搜；真正搜索直调 MiniMax HTTP 搜索接口（同 Key，无需 uvx） |

### 知识库目录与 Wiki（简要）

知识库页面使用逻辑目录，不把物理文件夹当作用户分类。`new_energy/*.md` 等源文档映射为“文档资料”，CSV/Excel 映射为“结构化数据”，`wiki`/`entities`/`05_Metrics` 分别映射为知识卡片、实体关系和指标规则，`reports`/`10_Outputs` 映射为报告成果；同一报告的 MD/Word/PDF 合并为一个逻辑成果。业务标签和治理状态可叠加筛选，但不会移动源文件或改变检索范围。

| 目录 | 用途 |
|------|------|
| `vault/wiki/` | **自动生成的文档要点卡**（写作检索第一优先）；也可手写补充 |
| `vault/raw/` / `vault/raw/raw/{三类}` | 原始资料留底；「导入 raw」从此扫描 |
| `vault/pipelines/` | 管网路由/站场表 |
| `vault/new_energy/` | 新能源政策 |
| `vault/dataqa/` | 统计问数表 |
| `vault/entities/<type>/` | 自动实体名片（脏名会拦截；站场会回填关联指标） |
| `vault/05_Metrics/` | 指标口径卡片（可 `POST /api/realai/metrics/seed` 种子） |

**共享导入流（问答与战略写作同一套文件）**：基础文件放入 `raw/raw/{pipelines,new_energy,dataqa}` → 导入 raw（质量门禁：空壳 HTML/过短正文拒绝；内容指纹去重）→ 写入业务目录 → 自动生成 `wiki/` 要点卡 + 实体页 → 批导末尾一次重建图谱。工作台与写作页面向用户统一使用七种逻辑知识类型；写作 API 以 `type:<knowledge_type>` 传递范围，后端再按知识目录分类器匹配物理文件。历史任务保存的 `wiki/raw/pipelines/...` 目录范围继续兼容。

导入 CSV 会丢弃 Geometry 等坐标列；Excel 会按工作表保留清洗后的 `.csv` 副本供问数，并记录表标题、工作表名、单位、年份布局和维度列。系统同时支持“年份在行”的长表与 `2026年 / 2027年 / …` 横向展开的宽表；精确问数优先走确定性查询，候选表置信度不足时不会再拿无关表的前几行冒充答案。健康度会显示 wiki 卡数、过短文档、脏实体、问答/写作就绪等（「可扫样本」仅为扩展名统计）。

图表按问题意图生成：只有用户明确提出图表、趋势、对比、排名或分布时才生成；单值问数不生成图，技术 ID、编码和常量列不会作为横轴。宽年份表可直接生成按年份展开的折线趋势。

**问数黄金问句（验收）**

| 问句 | 期望 |
|------|------|
| `中卫压气站` | 出现实体名片；问数卡含四线/三线中段等命中行；**不弹**条件确认卡；不出现无关表前几行预览 |
| `列出管径(mm)1422.0 设计压力10.0 管段长度大于80Km 的所有管段` | 轨迹含「等待确认筛选条件」；确认卡可改运算符/数值；点确认后一张合并总表（含来源文件）；无命中时明确说明 |
| `介绍一下 济南西分输清管站_泰安压气站` | 管段行级命中 +（可选）Skill 介绍模板 |
| 含「成本 / 某年」的统计问 | 轨迹可见 SQL问数或多表关联；结果带口径说明 |
| `北京2027年天然气预测数据是多少` | 对年份宽表直接返回“北京 / 2027年”的精确单值及来源；不生成无关图表、不回退到管线表 |
| `用折线图展示北京天然气预测趋势` | 使用宽表中的连续年份列生成折线图，横轴为年份，不使用 ID/编码列 |

密钥不要提交到 git。

## 6b. 评测中心怎么用

1. 打开左侧菜单 **评测中心**。
2. 若是空的：点 **一键导入示例黄金套件**（轻量问答约 30 题 + 报告 2 题）。
3. 选中套件 → 点 **跑批**（可选「联网」；勾选=强制搜网，未勾选=绝不搜网，避免智能抖动）。
4. 跑完后点 **详情**：看每题通过/失败/跳过原因、答案预览；按类别汇总；相对上次的新增失败题。
5. 高级：可填模型覆盖（记入快照）、写作/评审 Skill Id（报告套件对比用）。
6. 支持 **导出/导入 JSON**，方便备份与协作。

说明：筛选类题目在评测里会**自动确认**默认条件（工作台仍弹确认卡）。图表类无能力时记为「跳过」，不算假通过。健康度里的通过率仅在有真实跑批后才有值。

## 7a. 本地一键启动（开发）

更完整的「编译生效 / 分步启动 / 便携打包」说明见 **[docs/START.md](docs/START.md)**。

双击或在项目根目录运行（macOS / Windows）：

```text
./Start-RealAi-Dev.command
Start-RealAi-Dev.bat
```

等价命令：`npm run dev`

依次：**检查依赖 → 启动后端 → 启动 Vue（vite）→ 打开 Electron**。  
启动器会把 backend 与 `backend/packages/harness` 一并加入 `PYTHONPATH`；
根目录启动、完整开发启动和 Electron 自动拉起使用相同模块路径，Gateway
重启后不会出现 `No module named 'deerflow'`。  
可选：`Start-RealAi-Dev.bat --deerflow` 同时后台启动 DeerFlow React（不自动打开窗口）。

| 参数 | 说明 |
|------|------|
| `--build` | 启动前先 `npm run web:build` |
| `--install` | 强制重装 Vue 依赖 |
| `--no-electron` | 只启后端+Vue，浏览器访问 8402 |
| `--fresh` | 释放 8400/8401/8402 端口 |
| `--deerflow` | 额外启动封存的 DeerFlow Next |

首次使用前请确保已执行过 `npm run backend:sync`（Python 依赖）与 `npm run web:install`。

**若日志出现 `WinError 10048` / 端口占用：** 运行 `Start-RealAi-Dev.bat --fresh`。

## 8. 风险（摘要）

内嵌运行时打包难、多 Agent 耗时与费用、证据约束被绕过——用只读 SQL、证据包硬规则、轻量/报告分流缓解。若旧写作任务的「战略主线」里出现英文思考/`<think>`，刷新页面后会自动隐藏杂质；要得到规范中文主线请**新建任务重新运行**（或终止后重跑）。
